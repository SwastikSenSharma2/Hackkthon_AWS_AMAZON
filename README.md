# ACO Urban Traffic Routing Engine

> **Ant Colony Optimisation-based multi-modal traffic routing with heterogeneous vehicle prioritisation.**  
> Prototype city: Pune, Maharashtra, India (Jan 2023 CCTV data).  
> Architecture: city-agnostic — swap the `config/pune_config.yaml` inputs to run on any city.

---

## The Problem

Traffic gridlock is a universal, systemic failure caused by individually rational but collectively destructive behaviour: single-occupancy cars optimising only for their own travel time crowd out high-capacity public transport. This engine proposes a swarm-intelligence solution.

---

## The Solution: Modified Ant Colony Optimisation

Classic ACO simulates virtual ants depositing pheromone trails on shorter paths, creating a positive feedback loop that converges on optimal routes. This implementation introduces **five custom mutations** for real urban traffic:

| Mutation | Name | What it does |
|---|---|---|
| **A** | Dynamic Negative Pheromones | Roads spike with repellent signal when V/C ratio exceeds threshold — prevents artificial gridlock |
| **B** | Heterogeneous Perception | Transit buses (W_v=0.5) partially ignore congestion; single-occupancy cars (W_v=2.0) are pushed to side roads |
| **C** | Directional Candidate Lists | Edges moving an ant backwards toward the destination are pruned — saves compute, prevents geometric nonsense |
| **D** | Volatile Suffix Memoization | Caches optimal route tails; auto-invalidates when cached path becomes congested |
| **E** | Turn Penalties | Right-turn-across-traffic adds 45s; U-turns add 60s — swarm naturally finds ring-road routing |

## Project Structure

```
ACO_Traffic/
├── config/
│   └── pune_config.yaml          ← ALL tunable parameters live here
├── pipeline/
│   ├── 1_graph_builder.py        ← Parse GraphML → enriched NetworkX graph
│   ├── 2_traffic_loader.py       ← Build diurnal curve from CCTV data
│   ├── 3_fleet_composer.py       ← Modal share → vehicle class distribution
│   ├── 4_transit_anchorer.py     ← Snap GTFS stops → O-D transit agents
│   └── 5_agent_matrix.py         ← Assemble unified sorted agent list
├── aco/
│   ├── pheromone_map.py          ← Positive + negative pheromone state
│   ├── mutations.py              ← All 5 mutations as pure functions
│   ├── ant.py                    ← Single ant: builds one route
│   └── colony.py                 ← Colony: iteration loop, deposit, cache
├── scheduler/
│   └── departure_stagger.py      ← Spread transit departures to prevent bunching
├── simulation/
│   └── runner.py                 ← Main entry point: time-step loop
├── output/
│   └── results_writer.py         ← Write routes, edge loads, GeoJSON, summary
├── visualizer/
│   └── map_renderer.py           ← Folium HTML map with pheromone/load overlays
├── api/
│   └── main.py                   ← FastAPI: SSE streaming + REST endpoints
├── DATA/                         ← Pune dataset (do not modify)
├── processed/                    ← Generated by pipeline (gitignored)
├── output/                       ← Generated by simulation (gitignored)
├── requirements.txt
└── README.md
```

## Usage (run on GPU machine — DO NOT run on weak laptop)

### Step 1: Preprocessing Pipeline (run in order)

```bash
python pipeline/1_graph_builder.py --config config/pune_config.yaml
python pipeline/2_traffic_loader.py --config config/pune_config.yaml
python pipeline/3_fleet_composer.py --config config/pune_config.yaml
python pipeline/4_transit_anchorer.py --config config/pune_config.yaml
python pipeline/5_agent_matrix.py --config config/pune_config.yaml
```

Each stage writes to `processed/`. Total runtime on a laptop: ~2–5 minutes.

### Step 2: Departure Stagger (optional but recommended)

```bash
python scheduler/departure_stagger.py --config config/pune_config.yaml
```

### Step 3: Run Simulation

```bash
# Quick debug run (100 agents, 10 iterations)
python simulation/runner.py --agents 100 --iterations 10

# Full run (500 agents, 100 iterations)
python simulation/runner.py

# Full run without tqdm (for log files)
python simulation/runner.py --no-progress
```

### Step 4: Render Map

```bash
python visualizer/map_renderer.py
# Opens output/pune_pheromone_map.html in your browser
```

### Step 5: Start the API (for Next.js frontend)

```bash
uvicorn api.main:app --host 0.0.0.0 --port 8000 --reload
# Swagger UI: http://localhost:8000/api/docs
```

## ACO Parameter Reference (from `pune_config.yaml`)

| Parameter | Default | Effect |
|---|---|---|
| `alpha` | 1.0 | Pheromone influence — higher = swarm follows crowd |
| `beta` | 2.5 | Heuristic influence — higher = swarm greedily picks short roads |
| `rho` | 0.1 | Positive evaporation rate — higher = faster forgetting |
| `colony_size` | 50 | Ants per iteration — higher = better exploration, more compute |
| `iterations` | 100 | Iterations per agent — higher = better convergence |
| `neg_pheromone_scale` | 5.0 | Congestion repulsion strength |
| `vc_threshold` | 0.7 | V/C ratio above which negative pheromone activates |

## Adapting to a New City

1. Replace data files in `config/your_city_config.yaml → data:` section
2. Provide a GraphML road network (via OSMnx or any GIS tool)
3. Provide vehicle count CSVs with the same column schema
4. Provide GTFS transit stops + routes
5. Provide modal share CSV
6. Run the pipeline — no code changes required
